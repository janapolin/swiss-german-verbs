## 1. What this is

A local web app for drilling **Zurich German (Züritüütsch)** verb conjugation with
spaced repetition. A card shows an English prompt (gloss + tense + person), e.g.
`to do — he — past`; the learner taps to reveal the conjugated Swiss German answer,
e.g. `er het gmacht`, then self-grades ** good / hard**. Hard shortens the
interval so the card returns sooner.

**Scope (v1)**
- Single machine, local only — but the schema MUST support multiple **profiles**
  (multi-user) so it can grow later without a migration rewrite.
- Direction: **English → Swiss German** only. (Future: High German → Swiss German.
  Keep the prompt-language a field, not a hardcode.)
- Mode: **tap-to-reveal + self-grade** only. No typed-answer mode.
- Tenses drilled: **present, perfect (the only past tense in Zdt), future, Konjunktiv II**.

**Non-goals (v1)** — typed input, audio, conjugation of arbitrary unknown verbs,
example sentences, animations, accounts/auth/cloud.

## 4. The central modeling rule

**A card is a `(verb × tense × person)` slot, not a verb.** SRS state lives per
slot, because a learner may know `er het gmacht` but not `ich mache`.

- `person ∈ {sg1, sg2, sg3, pl}` — plural collapses 1./2./3. person (identical in Zdt).
- `tense ∈ {present, perfect, future, konj2}`.
- Stable card key: `f"{verb_id}:{tense.value}:{person.value}"`.

Per verb: present/perfect/future × 4 persons = **12 cards**,
plus konj2 × 4 **only if** `has_konjunktiv2 = true` (see §6).

---

## 5. Stored data vs derived forms

Only these forms are **stored** per verb. For separable verbs all stored forms are
**bare** (prefix stripped, kept in `verbs.separable_prefix`):

```
present_sg1, present_sg2, present_sg3, present_pl
participle
konj2_sg1, konj2_sg2, konj2_sg3, konj2_pl  ← nullable; only if has_konjunktiv2
```

**Regular verbs:** the four present forms are **generated by rule** in `expand_regular.py`
(§13) and are NOT in `verbs_regular.csv`. The **participle** is irregular enough that
it is stored explicitly in the CSV.

**The infinitive is stored fully attached** (`uufhänke`, not `hänke`).

Perfect, future, and the pronoun are NEVER stored — the rendering engine builds them.

## 6. The rendering engine (`domain/rendering.py`) — the core; test it first

Signature: `render(verb: Verb, tense: Tense, person: Person) -> str`
Returns the **back of the card**: pronoun + conjugated form. Pure; no I/O.

**Pronouns** (configurable, English labels alongside):

| person | Zdt pronoun | English label |
|--------|-------------|---------------|
| sg1    | ich         | I             |
| sg2    | du          | you           |
| sg3    | er          | he            |
| pl     | mir         | we            |

**Tense labels** (English, shown on the card's tense pill):
`present → "Present"`, `perfect → "Past"`, `future → "Future"`,
`konj2 → "Would (Konj. II)"`.

**The engine depends on the present-tense tables of three auxiliaries** loaded from
the DB by infinitive at startup:
- `ha` (perfect aux for ha-verbs): `han / häsch / het / händ`
- `si` (perfect aux for si-verbs): `bin / bisch / isch / sind`
- `werde` (future aux for all): `wird / wirsch / wird / wèèrded`

(Exact forms live in `data/verbs_irregular.csv`; the engine reads them from there via
the repository. Do not hardcode them in the engine itself.)

**Rendering rules:**

- **present**
  - non-separable: `f"{pronoun} {present_form}"` → `er macht`
  - separable: `f"{pronoun} {present_form} {prefix}"` → `er hänkt uuf`

- **perfect** (the only past tense in Zdt)
  - aux_verb = `ha` if `verb.aux == "ha"` else `si`
  - aux_form = that aux verb's present form for this person
  - participle_full = `f"{prefix}{participle}"` if separable else `participle`
  - result: `f"{pronoun} {aux_form} {participle_full}"` → `er het gmacht`,
    `er isch uufghänkt`

- **future** = present of `werde` + full attached infinitive
  - result: `f"{pronoun} {werde_form} {verb.infinitive}"` → `er wird mache`,
    `er wird uufhänke`

- **konj2**
  - if `not verb.has_konjunktiv2`: slot does not exist — `card_gen` must NOT emit
    it. No periphrastic `wür` fallback in v1.
  - separable: `f"{pronoun} {konj2_form} {prefix}"` — same placement as present
  - non-separable: `f"{pronoun} {konj2_form}"` → `er hätt`

**Override hook:** any `verb_forms` row may carry `is_override = true` and a full
pre-assembled string that bypasses rule-based assembly entirely. This lets irregular
separables be hand-corrected without touching the engine.

**`tests/test_rendering.py` must cover** (use rows from `data/verbs_irregular.csv`
and `data/verbs_regular.csv`):
- a regular class-A verb: `mache` (ha, non-separable) in all four tenses
- a separable verb: `uufhänke` (ha, prefix `uuf`) — present, perfect, future
- perfect with `si`: `choo` (si) — `er isch choo`
- KII: `ha` → `er hätt`, `si` → `er wär`, `wele` → `er wett`
- future of `werde` itself (edge case): `er wird werde`

## 7. Trennbare (separable-prefix) verbs

Chosen approach: **rule-based assembly with a per-cell override** (clean where the
language is regular, exact where it isn't — see override hook in §6).

**Separable prefixes** (from the source data; detect by longest-prefix match):

```python
SEPARABLE_PREFIXES = [
    "iine-", "nache-", "zäme-", "dure-", "wäg-",
    "uuf-", "uus-", "zue-", "abe-", "ufe-",
    "aa-", "ab-", "ah-", "ii-", "um-", "uf-",
    "mit-", "vor-",
]
# longest-first so "iine-" matches before "ii-"
```

**Inseparable prefixes** (never detach; participle takes NO `g-`):
`ver-, be-, ent-, er-, ge-, zer-`

**Placement rule:**
- prefix **attached**: infinitive, participle, future infinitive → `uufghänkt`, `uufhänke`
- prefix **detached to clause end**: finite present + finite Konj II → `er hänkt uuf`

## 8. Spelling normalisation (`ingestion/normalize.py`)

The source uses two non-standard glyphs that must be normalised on ingestion.
Implement as an ordered `(pattern, replacement, position)` table — trivial to
correct and unit-test:

| Glyph observed | Rule | Example |
|---|---|---|
| doubled grave-e `èè` (source uses `éé` or `èè`) | `ee` word-internal, `eh` word-final | `fèèle → feele`, `lèère → leere` |
| o-with-dot(s)-above `ȯȯ` ("triple-umlaut o") | → `ö` | `rȯȯtle → röötle` |

> **Still TBD:** confirm the exact Unicode codepoints of both glyphs from the raw
> PNG bytes so `normalize.py` matches them precisely. The rules and affected words
> are clear; only the byte-level pattern needs locking down.

## 9. Auxiliaries (`ha`, `si`, `werde`)

Stored as **ordinary verb rows** (`is_auxiliary = true`) — single source of truth.
The rendering engine loads their present tables via the repository at startup.
They are also drillable as cards: for `is_auxiliary = true`, `card_gen` emits
**present-tense cards only** by default (their own compound tenses are edge-casey);
expose this as a boolean config flag.

`verbs.aux` (which auxiliary a verb uses in the perfect) is `'ha'` or `'si'` only.
`werde` is the future auxiliary for all verbs and is NOT a value of `verbs.aux`.

Known auxiliary `verb.aux` assignments (from `data/verbs_irregular.csv` + the
regular perfekt sheet):
- **si-verbs** (irregular): `si, ga, cho, stah*`  (* = VERIFY with owner)
- **si-verbs** (regular): `bliibe, faare, falle, lauffe, renne, schwüme, springe,
  umcheere, sitze, räise`
- Everything else: **ha** (incl. `ligge`, `früüre`, `zügle`, `folge`, `hange`,
  resolved by the owner — see §17).

## 10. Scheduler (`domain/scheduler.py`)

Define an abstract interface so the algorithm can be swapped (FSRS later):

```python
class Scheduler(Protocol):
    def grade(self, state: ReviewState, grade: Grade) -> ReviewState: ...
    def pick_next(self, profile_id: int, today: date) -> Card | None: ...
```

Ship **`Sm2Scheduler`** (3-button SM-2 variant).

`ReviewState` fields: `ease_factor` (default 2.5), `interval_days`, `repetitions`,
`lapses`, `due_date`.

Grade mapping to SM-2 quality:
- `hard` → quality 2: reset repetitions, short interval (1 day), lower ease. Returns soon.
- `good` → quality 4: normal interval growth.

`tests/test_scheduler.py` must assert:
- hard reliably shortens interval vs good
- repeated good grades grow interval geometrically

**Card selection / session logic** (in a `SessionService`, not in the route):
1. Serve **due** reviews first (`due_date ≤ today`), ordered by `due_date` ascending.
2. Introduce **new** cards in ascending `frequency_rank`, up to a configurable daily
   new-card limit (default 10). Create the `review_state` row lazily on first encounter.

## 11. Data model

**Content tables** (rebuildable from ingestion; never hold user progress):
```
verbs:      id, infinitive, english_gloss, frequency_rank, verb_class (A|B|C|null),
            separable_prefix (nullable), aux ('ha'|'si'), has_konjunktiv2 (bool),
            is_auxiliary (bool), notes

verb_forms: verb_id (FK), form_key, value, is_override (bool, default false)
            form_key ∈ {present_sg1, present_sg2, present_sg3, present_pl,
                        participle, konj2_sg1, konj2_sg2, konj2_sg3, konj2_pl}
            UNIQUE (verb_id, form_key)
```

**User-state tables** (per profile; survive content rebuilds):
```
profiles:      id, name, created_at

review_state:  id, profile_id (FK), card_key, ease_factor, interval_days,
               repetitions, lapses, due_date, last_reviewed_at
               UNIQUE (profile_id, card_key)

review_log:    id, profile_id (FK), card_key, grade, reviewed_at   ← append-only
```

## 12. API (`app/api`)

Keep routes thin — they call services, they do no logic.

- `GET  /api/next?profile_id=` → `{ card_key, front: {gloss, tense_label, person_label}, back: {answer} }`
  (back is included; the UI hides it until tap — no second round-trip needed)
- `POST /api/grade` `{ profile_id, card_key, grade }` → `{ ok: true }`
- `GET  /api/profiles`, `POST /api/profiles { name }`

HTMX: routes may return rendered Jinja partials instead of JSON — either is fine,
but logic stays in the service layer regardless.

**Grade buttons:** the UI shows **three** segments at the bottom of the revealed
card — red `Hard` (left), green `Good` (right). This differs
from the two-button reference app (thumbs up/down); use the reference for visual
style only.

## 13. Ingestion pipeline (`ingestion/`, offline, idempotent)

**Seed data files** (already prepared, in `data/`):

| File | Contents |
|------|----------|
| `data/verbs_irregular.csv` | 26 irregular verbs (incl. `ha`, `si`, `werde`), fully conjugated |
| `data/verbs_regular.csv`   | ~120 regular verbs: infinitive, gloss, class (A/B/C), separable_prefix, aux, explicit participle |
| `data/grammar_rules.md`    | Class A/B/C present-ending rules, aux assignment rule, normalisation rules, KII table |

**`expand_regular.py`** — generates the four present forms for regular verbs from
`grammar_rules.md` §1. The stem is the infinitive minus its trailing `e` (strip the
separable prefix first, if any). Endings by class:

| | sg1 | sg2 | sg3 | pl |
|-|-----|-----|-----|----|
| A | `-e` | `-sch` | `-t` | `-ed` |
| B | `-e` | `-isch` | `-et` | `-ed` |
| C | `-e` | `-isch` | `-t` | `-ed` |

C only applies after stems ending in `s, sch, ss, tz, z`.

**`ingest.py`** CLI pipeline (in order):
1. Load `verbs_irregular.csv` — all forms stored as-is.
2. Load `verbs_regular.csv` — call `expand_regular` to generate present forms; participle is in the CSV.
3. Apply `normalize.py` to all string values.
4. Detect separable prefix via `prefixes.py` (longest-match against `SEPARABLE_PREFIXES`); strip it from stored present forms and participle; store in `verbs.separable_prefix`.
5. Validate each verb has all four present forms + participle; konj2 all-or-nothing.
6. Upsert by `infinitive` (re-running is always safe).

**`frequency_rank`** is not in the source data. Seed strategy: assign ranks 1–26
to the irregular verbs (they are explicitly "die wichtigsten"), then 27–N to
regular verbs in CSV row order. Owner can reorder later without touching the SRS
state (the card key uses `verb_id`, not rank).

## 15. Conventions

- Pure domain, framework-free; repositories isolate all DB access; routes are thin.
- Full type hints; frozen dataclasses for domain models; enums for Tense/Person/Grade.
- Every schema change is an Alembic migration — never hand-edit tables.
- Config (new-cards/day, aux-cards-present-only, plural pronoun) in one settings
  module, read from env with sane defaults. No magic numbers in business logic.
- Tests written alongside each function. The rendering engine and scheduler are pure
  and must have the highest coverage.
- Naming: English identifiers; Züritüütsch domain terms (`konj2`, `aux`,
  `participle`, `werde`) used consistently.
